# Supabase Redirect URL Fix

## Issue
Google OAuth works, but redirects to `localhost` instead of the app's deep link.

## Root Cause
Supabase needs the redirect URL to be:
1. **Added to Supabase Dashboard** → Authentication → URL Configuration
2. **Properly formatted** using `makeRedirectUri()` from `expo-auth-session`

## Solution

### Step 1: Get Your Redirect URL

The redirect URL is generated by `makeRedirectUri()` and will be something like:
- **Expo Go (Development)**: `exp://10.0.0.73:8081/--/auth/callback` (IP address varies)
- **Custom Scheme (Production)**: `values://auth/callback`

**Check your console logs** for: `[DEBUG] App redirect configuration` to see the exact redirect URI.

### Step 2: Configure Supabase Dashboard (CRITICAL - THIS FIXES THE LOCALHOST ISSUE)

**This is the root cause of the "Safari can't connect to server" error!**

When Supabase redirects to `localhost`, it means the redirect URL isn't configured in Supabase Dashboard. You MUST configure both:

#### A. Default Site URL

1. Go to [Supabase Dashboard](https://supabase.com/dashboard)
2. Select your project: `nkcaaujkovelpqahmuug`
3. Go to **Authentication** → **URL Configuration**
4. Under **Site URL**, change from `localhost` to:
   ```
   https://nkcaaujkovelpqahmuug.supabase.co
   ```
   Or use your production domain if you have one.
   
   **Why?** The Site URL is used for email templates and other features. `localhost` won't work for these.

#### B. Redirect URLs

Still in **Authentication** → **URL Configuration**, under **Redirect URLs**, add these patterns (one per line):
   ```
   exp://**
   values://auth/callback
   values://**
   ```
   
   **Why multiple patterns?**
   - `exp://**` - Catches all Expo Go URLs (IP addresses vary, e.g., `exp://10.0.0.73:8081/--/auth/callback`)
   - `values://auth/callback` - Exact match for production
   - `values://**` - Wildcard for flexibility

5. **Click "Save"** - This is critical!

**After saving, Supabase will redirect to your app's deep link instead of localhost.**

### Step 3: Test Again

After adding the redirect URLs:
1. Restart your Expo app
2. Try Google sign-in again
3. Check the console logs for:
   - `[DEBUG] Browser result` - Should show `type: 'success'`
   - `[DEBUG] Full redirect URL` - Should show the redirect URL with tokens
   - `[DEBUG] Token extraction result` - Should show tokens found

### Step 4: If Still Redirecting to Localhost

If Supabase still redirects to `localhost`, the code will:
1. Extract tokens from the `localhost` URL
2. Set the session manually using `supabase.auth.setSession()`
3. Complete authentication

**Check logs for:**
- `[DEBUG] Full redirect URL` - What URL does it show?
- `[DEBUG] Token extraction result` - Are tokens found?
- `[DEBUG] ✅ Session set successfully` - Did session get set?

## Current Code

The code now:
1. Uses `makeRedirectUri()` to generate the redirect URL
2. Passes it to Supabase OAuth: `redirectTo: redirectUri`
3. Opens the OAuth URL in browser: `WebBrowser.openAuthSessionAsync()`
4. **Extracts tokens from redirect URL** (handles localhost, exp://, values://)
5. **Sets session manually** if tokens found
6. Waits for auth state change event

## Debugging

If it still redirects to localhost:
1. Check console for `[DEBUG] App redirect configuration` - what's the `redirectUri`?
2. Verify that `exp://**` pattern is in Supabase Dashboard → Authentication → URL Configuration
3. Check `[DEBUG] Browser result` - what URL does it return?
4. Check `[DEBUG] Full redirect URL` - does it contain tokens?
5. Check `[DEBUG] Token extraction result` - are tokens found?

## Expected Flow After Fix

1. User taps "Continue with Google"
2. Browser opens with Google sign-in
3. User signs in
4. Supabase redirects to `exp://10.0.0.73:8081/--/auth/callback#access_token=...` (or localhost)
5. Code extracts tokens from redirect URL
6. Code sets session using `supabase.auth.setSession()`
7. Auth state change fires → User authenticated ✅
